화상 인터뷰 준비 (SnakeDefender)

30분 전후 가정. 말 그대로 읽지 말고 bullet만 보고 자연스럽게 말할 것.

1. 자기소개 (~1분)

뼈대

  • 이름 / 현재 소속·상태 (학생·수료·구직 등 한 줄)
  • 이번에 Unity로 세로 디펜스형 게임 과제 제출했고, 뱀이 경로를 따라 오는 적을 타워가 맞추는 구조로 구현함
  • 지금은 과제 전형 통과 후 인터뷰 단계라고 이해함

예시 문장 (톤만 참고)

안녕하세요. [이름]입니다. 이번에 SnakeDefender라는 프로젝트로 과제를 제출했고, 세로 스크린에서 뱀 형태 적이 웨이포인트 경로를 따라 이동하고 플레이어가 위로 사격해서 몸통·머리 HP를 깎는 게임입니다. README에 요구사항 대응이랑 동작 요약, 플레이 영상 링크까지 정리해 두었습니다.

2. 과제 설명 (~3~5분) 스크립트

한 줄 정의

  • 세로 디펜스 + 뱀 적 + 타워 사격 + 승패 + (선택) 광폭화·비스플라인 이동

흐름 순서로 말하기

  1. 적 이동
  2. 핵심은 PathRoute의 거리 기반 샘플링임. 웨이포인트를 선분으로 보고 각 구간 길이와 전체 길이를 캐시해 둠.
  3. 적(SnakeEnemy)은 매 프레임 headDistance += moveSpeed * deltaTime로 머리 진행 거리만 올림.
  4. 세그먼트는 인덱스별 뒤처짐 거리(GetDistanceBehindHead)를 써서 headDistance - gap 위치를 계산하고, GetTrackPoint로 월드 좌표를 가져와 배치함.
  5. 그래서 “머리 하나만 전진 계산 + 나머지는 상대 거리로 추종” 구조가 됨. 세그먼트 수가 늘어도 동작 규칙은 동일함.
  6. 경로 끝 이후는 마지막 웨이포인트에서 finalGoalTarget까지 Lerp로 연결해, 플레이어 위치가 바뀌면 마지막 구간도 같이 반영됨.

  7. 정리하면: 스플라인 없이도 거리 -> 좌표 변환으로 경로 이동/추종/끝구간 연결을 단순하게 풀었음.

  8. 몸통 파괴

  9. 파괴 이벤트가 오면 OnSegmentDestroyed에서 해당 몸통 세그먼트를 리스트/캐시에서 제거하고 오브젝트를 정리함.
  10. 그 다음 headDistance = Max(0, headDistance - segmentSpacing)로 머리 진행 거리를 한 칸 당김.
  11. 마지막에 RefreshSegmentPositions()를 즉시 호출해서, 머리/남은 몸통 전체 위치를 같은 프레임 기준으로 다시 계산함.
  12. 포인트는 “보이기만 하는 연출”이 아니라, 진행 거리 값 자체를 수정해서 경로상 위치가 실제로 뒤로 이동한다는 점임.

  13. 이 방식 덕분에 몸통이 빠진 뒤에도 간격 규칙이 깨지지 않고, 자연스럽게 압축되는 느낌으로 이어짐.

  14. 공격

  15. 타워가 쿨타임마다 위쪽으로 레이를 쏴서 맞을 수 있는 세그먼트가 있을 때만 발사.

  16. 총알은 세그먼트 HP를 깎고 0이면 파괴 처리.

  17. 승패

  18. 목표 처치 수를 채우면 승리.

  19. 머리가 플레이어에 닿거나 경로 끝까지 오면 실패.

  20. 선택 과제

  21. 몸통을 일정 수 이상 파괴하면 속도·머리 표정(스프라이트) 쪽 광폭화 느낌.

  22. 추가로 넣은 것

  23. 몸통 N개 파괴 시 스펙업 UI (공격력·공속·총알 수 중 선택).
  24. 플레이어 좌우 드래그 이동.
  25. 시작 시 멈춤·시작 버튼·ESC 종료 등 플레이 편의.

4. 기술 짧은 답 (한 문장씩)

주제 말할 내용
왜 스플라인 안 씀 과제 선택 요구 + 웨이포인트 거리 누적만으로 충분해서 패키지 의존 줄임
타워가 언제 쏨 위로 레이캐스트해서 맞을 세그먼트가 있을 때만 + 쿨타임
몸통 깨질 때 머리 진행 거리를 간격만큼 줄여서 경로상 위치가 실제로 당겨짐
승리 조건 전체 목표 처치 수 달성
실패 조건 머리가 플레이어 접촉 일정 시간 또는 경로 끝 도달
스펙업 몸통 N개마다 창 띄우고 공격력·공속·총알 수 중 선택
UI 몸통 HP·데미지는 월드 좌표를 캔버스에 붙임
시작 멈춤 시작 전 timeScale 0, 시작 버튼으로 진행
ESC 빌드 테스트 편하게 종료 (입력 시스템 기준)

5. 예상 질문 & 답변 초안

Q. 전체 구조를 한 번에 설명해 보세요.
→ 플레이어 타워 ↔ 총알 ↔ 뱀 세그먼트 HP ↔ 게임 매니저 승패. 적은 PathRoute로 경로 이동, 몸통 깨지면 진행 거리 조정으로 머리 당김.

Q. 승패는 어디서 판정하나요?
→ 게임 매니저에서 처치 수·목표 수 비교로 승리, 머리 접촉·경로 끝으로 실패.

Q. 왜 레이로 맞을 때만 쏘나요?
→ 빈 화면에 총알만 나가는 연출을 줄이고, “지금 맞출 대상이 있다”는 피드백을 맞추려고 했음. (다시 한다면 상시 발사도 검토 가능하다고 덧붙여도 됨.)

Q. 몸통 파괴 시 머리 당김은 어떻게 구현했나요?
→ 세그먼트를 리스트/캐시에서 제거한 뒤, 머리 진행 거리(headDistance)를 segmentSpacing만큼 줄이고 즉시 전체 위치를 재계산합니다. 그래서 실제 경로 좌표가 뒤로 이동합니다.

Q. 적 이동을 왜 거리 기반으로 했나요?
→ 시간 기반으로 좌표를 직접 누적하면 세그먼트 추종과 끝구간 연결에서 케이스가 늘어납니다. 거리 기반으로 두면 “거리만 정하면 좌표가 나오는” 공통 규칙으로 묶여서 구현/디버그가 단순해집니다.

Q. 스플라인 안 쓴 이유는?
→ 선택 요구사항 충족 + 웨이포인트 거리 기반이면 구현·디버그가 단순함.

Q. 광폭화는 어떻게 표현했나요?
→ 몸통 파괴 수에 따라 단계 바꾸고, 분노 시 속도 올리고 머리는 스프라이트·색으로 표현.

Q. 추가 기능 중 가장 신경 쓴 것은?
→ 스펙업 UI와 타워 수치 연동, 또는 드래그 이동과 목표 지점 동기화 중 하나 골라서 한두 문장.

Q. 시간 부족했을 때 뭘 먼저 끊었을 것 같나요?
→ 필수 먼저, 선택·추가는 이후. README·영상은 제출물 설명용이라 가능하면 유지.

Q. 혼자 한 프로젝트인가요?
→ 혼자 / 팀이면 역할 분담 한 줄.

Q. 이 프로젝트에서 본인의 강점은?
→ 요구사항 정리·README·빌드 가능한 완성도 / 문제 나눠서 구현한 점 등 사실 기반으로 한 가지.

Q. 약점이나 아쉬운 점은?
→ 파일 크기·성능 프로파일 미실시·테스트 자동화 없음 등 한 가지 + 개선 방향 한 줄.

Q. 우리 회사·과정에 왜 지원했나요?
→ (본인이 채울 부분) 교육과 실무 사이, 커리큘럼, 포지션 기대 등 짧게 진심 한 스푼.
